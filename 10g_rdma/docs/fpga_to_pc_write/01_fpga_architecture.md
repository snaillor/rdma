# FPGA -> PC 单向 RDMA Write 架构设计

## 1. 系统概述

本方案实现 FPGA 作为 RDMA Initiator，PC 作为 RDMA Target 的单向数据传输。FPGA 通过 RoCEv2 协议将数据写入 PC 内存，PC 软件负责接收并确认。

## 3. 关键数据流

### 3.1 发送路径 (WQE -> RoCEv2 包)

```
DDR WQE ──► AXI Master ──► wqe_proc_top ──► wqe_proc_hdr_gen
                                              │
                                              ▼
                                    ┌─────────────────────┐
                                    │ 包头组装 (512-bit)   │
                                    ├─────────────────────┤
                                    │ [ETH: 14B]          │
                                    │ [IP: 20B]           │
                                    │ [UDP: 8B]           │
                                    │ [BTH: 12B]          │
                                    │ [RETH: 16B]         │
                                    │ [Payload: Variable] │
                                    │ [ICRC: 4B]          │
                                    └─────────────────────┘
                                              │
                                              ▼
                                    TX AXI-Stream ──► 10G MAC
```

### 3.2 ACK处理路径

```
10G MAC ──► RX AXI-Stream ──► rx_pkt_handler
                                      │
                                      ▼
                              解析 BTH Opcode=0x11 (ACK)
                                      │
                                      ▼
                              提取 AETH (Syndrome + MSN)
                                      │
                                      ▼
                              resp_handler_fsm
                              ├─ PSN 范围比较
                              ├─ 清除 OSQ 条目
                              ├─ 释放数据缓冲
                              └─ 触发重传 (如有 NAK)
```

### 3.3 超时重传路径

```
resp_handler_timer ──► PSN 超时检测
                              │
                              ▼
                    设置 i_osq_timed_out
                              │
                              ▼
                    resp_handler_fsm
                              │
                              ▼
                    触发 o_retransmit_reqd
                              │
                              ▼
                    wqe_proc_hdr_gen (重新发送)
                              │
                              ▼
                    从重传缓冲读取数据
```

## 4. WQE 格式 (FPGA 内部)

WQE (Work Queue Entry) 是驱动软件在 DDR 中准备的描述符，FPGA 通过 AXI Master 读取：

```
WQE 结构 (64 字节，512-bit 对齐):

Byte 0-1:   WQE 类型 / 控制字段
            ├─ [7:0]  Opcode: 0x06=WRITE_FIRST, 0x08=WRITE_LAST, 0x0A=WRITE_ONLY
            └─ [15:8] 标志位

Byte 2-3:   WR_ID (工作请求标识，用于完成通知)

Byte 4-7:   保留

Byte 8-11:  本地数据长度 (字节)

Byte 12-15: 保留

Byte 16-23: 本地数据源地址 (DDR 中的数据地址)

Byte 24-31: 远程目标地址 (PC 内存的虚拟地址 VA)

Byte 32-35: R_Key (远程内存访问密钥)

Byte 36-39: 远程写入长度

Byte 40-47: 保留 (SGL 列表等，单向 Write 可不用)

Byte 48-63: 保留
```

## 5. 配置寄存器 (AXI-Lite)

软件通过 AXI-Lite 配置以下参数后，再启动传输：

### 5.1 全局配置

| 地址偏移 | 寄存器名 | 位宽 | 说明 |
|----------|----------|------|------|
| 0x000 | `RDMA_EN` | 1 | RDMA 使能 (写 1 启动) |
| 0x004 | `MAC_SRC` | 48 | FPGA 源 MAC 地址 |
| 0x00C | `IPV4_SRC` | 32 | FPGA 源 IPv4 地址 |
| 0x010 | `UDP_SRC_PORT` | 16 | UDP 源端口 |
| 0x014 | `IP_VER` | 1 | 0=IPv4, 1=IPv6 |

### 5.2 QP 配置 (单 QP 固定地址)

| 地址偏移 | 寄存器名 | 位宽 | 说明 |
|----------|----------|------|------|
| 0x200 | `QP_EN` | 1 | QP 使能 |
| 0x204 | `DEST_MAC` | 48 | PC 目的 MAC 地址 |
| 0x20C | `DEST_IP` | 32 | PC 目的 IPv4 地址 |
| 0x210 | `DEST_QPN` | 24 | PC 端 QP 号 |
| 0x214 | `SRC_QPN` | 24 | FPGA 端 QP 号 |
| 0x218 | `SQ_PSN` | 24 | 发送起始 PSN |
| 0x21C | `PKEY` | 16 | Partition Key |
| 0x220 | `PMTU` | 3 | 包 MTU (0=256,1=512,2=1024,3=2048,4=4096) |
| 0x224 | `SQ_BA` | 32 | 发送队列 WQE 基地址 (DDR) |
| 0x228 | `SQ_DEPTH` | 16 | 发送队列深度 |
| 0x22C | `CQ_BA` | 32 | 完成队列基地址 (DDR) |
| 0x230 | `CQ_DEPTH` | 16 | 完成队列深度 |
| 0x234 | `TIMEOUT` | 5 | 重传超时时间配置 |
| 0x238 | `RETRY_CNT` | 3 | 最大重试次数 |

### 5.3 数据缓冲配置

| 地址偏移 | 寄存器名 | 位宽 | 说明 |
|----------|----------|------|------|
| 0x300 | `DATA_BUF_BA` | 32 | 重传数据缓冲基地址 |
| 0x304 | `DATA_BUF_NUM` | 16 | 缓冲数量 |
| 0x308 | `DATA_BUF_SZ` | 16 | 单个缓冲大小 |

## 9. PSN 管理规则

### 9.1 PSN 分配

- 每个 WQE 分配一个起始 PSN (`start_psn`)
- 如果 Payload 超过 PMTU，分包发送：
  - 第一包: Opcode = WRITE_FIRST, PSN = start_psn
  - 中间包: Opcode = WRITE_MIDDLE, PSN = start_psn + 1, 2, ...
  - 最后一包: Opcode = WRITE_LAST, PSN = start_psn + n
- 单包写: Opcode = WRITE_ONLY, PSN = start_psn

### 9.2 ACK PSN 确认范围

- ACK 的 PSN 表示该 PSN 及之前的所有包都已成功接收
- 例: 发送 PSN=100,101,102，收到 ACK PSN=102，表示 100~102 全部确认
- Outstanding Queue 中 `end_psn <= 102` 的条目可以弹出

### 9.3 NAK 处理

- NAK 携带 Syndrome 和 PSN
- Syndrome 0x81 (Sequence Error): 从该 PSN 开始重传
- Syndrome 0x80 (RNR NAK): 延迟重传
- 重传时保持原 PSN 不变

## 10. 中断与完成通知

### 10.1 FPGA -> 软件中断

| 中断源 | 说明 | 触发条件 |
|--------|------|----------|
| `wqe_cmpl_intr` | WQE 完成中断 | WQE 被 ACK 确认 |
| `retry_exceeded_intr` | 重试超限中断 | 重试次数达到上限 |
| `timeout_intr` | 超时中断 | 定时器超时 |

### 10.2 完成队列 (CQ) 条目

```
CQE 结构 (16 字节):

Byte 0-1:   WR_ID (来自 WQE)
Byte 2-3:   状态码 (0=成功, 其他=错误码)
Byte 4-7:   保留
Byte 8-11:  发送字节数
Byte 12-15: 保留
```

软件通过读取 CQ 获取发送完成状态，或通过中断异步通知。
